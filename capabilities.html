What works where

An honest list for each platform: what is supported, how it works, and how it can be bypassed. The same information is in the app under Settings → Capabilities, so you can check it on your own device.

Android (8.0 and newer)

Real enforcement, no root and no device owner. Needs two permissions you grant in system Settings: Usage access (statistics) and Accessibility (seeing which app is in front and opening the block screen). Notifications are optional.

FeatureSupportedHowLimits and bypasses
Screen-time trackingYesUsageStatsManager (Usage access). Works with all restrictions off.Android keeps detailed events only for a limited time, so Lentivault saves daily summaries itself. Foreground time is not the same as screen-on time.
Per-app daily limitsYesAccessibility service compares usage with the plan.Turning off the accessibility service or uninstalling ends enforcement.
Launch limitsYesApp openings counted from usage events and the service.Same as above.
Continuous-use limitsYesSession length measured while the app stays in front.Briefly switching apps may count as a break.
Block screenYesNative screen opened over the app; Go home, Emergency call.There can be a short moment before the block screen appears.
Friction / pause screenYesNative countdown, breathing, reason prompt.Same as block screen.
Schedules and timersYesEvaluated on the phone from the saved plan.Works with Lentivault closed.
Ultra Extreme lockWithin Android’s limitsNo in-app way out; locked entries in the plan.You can still disable the accessibility service in Settings, start in safe mode, or uninstall. Lentivault records the interruption.
Auto-renewalYesCycles written into the plan up to 60 days ahead, with a fallback rule beyond.Renews the restriction only; there is nothing to pay.
Website blockingPartlyReads the address bar of Chrome, Firefox, Samsung Internet, Edge, Brave, Opera and DuckDuckGo.Other browsers and in-app browsers are not covered. Block the browser app itself if you need certainty.
Feed hiding inside appsNoAndroid does not let apps hide one part of another app.Block the whole app, or use the browser version of the site with the extension.
NotificationsYesLocal notifications (Android 13+ asks for permission).Some manufacturers delay notifications in battery saving.
Home-screen widgetYesToday’s time, active restriction, next deadline.Android refreshes widgets at most every 30 minutes by itself; the app updates it when opened.
Quick Settings tileYesOne tap starts a Quick Block.Android 8+.
Uninstall frictionOne extra stepOptional Device Admin.Android always lets you turn Device Admin off in Settings, then uninstall. It is a pause, not a lock.
After restartYesPlan saved on the phone; service restarts after you unlock.Nothing is enforced before the first unlock after a restart.
Clock or time-zone changeYesMonotonic clock reference detects manual jumps; commitments keep their time zone.After a restart with automatic time off, the device clock has to be trusted again; Lentivault flags this.

Chrome, Edge, Brave and Opera extension

A Manifest V3 extension installed from a file (developer mode). Enforces inside that browser profile only.

Website blockingYesdeclarativeNetRequest dynamic rules redirect to a block page.Removing or disabling the extension ends it. Private windows only if you allow the extension there. Other browsers and profiles are not covered.
Per-site time limitsYesActive tab in the focused window, with the idle API.Approximate: background tabs and other browsers are not counted.
Schedules and timersYesAlarms at schedule boundaries.Only while the browser is running (rules persist across restarts).
Feed hidingYesContent scripts for YouTube, Instagram, Reddit, X, Facebook and LinkedIn.Can stop working when a site changes its layout until the extension is updated.
Infinite-scroll brakeYesOverlay after a set number of screen heights.Site-specific scrolling may differ.
Locked commitmentsWithin the browser’s limitsOptions page refuses to weaken them.The browser always lets you remove the extension. Preventing that requires a managed (enterprise) browser.
After restartYesDynamic rules and storage persist.—

Firefox extension (128 and newer)

Same features as the Chromium extension. Firefox requires add-ons to be signed by Mozilla for permanent installation in its release version.

FeatureSupportedHowLimits and bypasses
Website blockingYesdeclarativeNetRequest.Removing or disabling the add-on ends it. Firefox may ask you to allow access to all websites; without it, blocking and feed hiding cannot run.
Time limits, schedules, feed hidingYesSame as Chromium.Same as Chromium.
InstallationPartlyTemporary add-on, or a signed file.A temporary add-on is removed when Firefox closes. Firefox for Android is not supported in 0.1.

Web app (any modern browser)

For planning, focus timers and trying Lentivault. A web page cannot see or block other apps or sites, and we label this clearly in the app.

iPhone and iPad (iOS)

Not available in version 0.1. Blocking apps on iOS requires Apple’s Screen Time API (Family Controls), which needs a special distribution entitlement from Apple, a paid developer account and a native app built with Xcode. iOS gives apps no equivalent of Android’s accessibility approach.

FeatureSupportedHowLimits and bypasses
EverythingNot builtWould use FamilyControls, DeviceActivity and ManagedSettings.You can use the web app in Safari for planning and focus timers, and Apple’s built-in Screen Time.

Safari (macOS, iOS)

Not available in version 0.1. Safari extensions have to be wrapped in a native app with Xcode and signed with an Apple developer account.

FeatureSupportedHowLimits and bypasses
EverythingNot builtWould be a Safari Web Extension from the same code.Use Chrome, Edge, Brave, Opera or Firefox on desktop.

Desktop apps (Windows, macOS, Linux)

Not available in version 0.1. The browser extension covers websites only; native desktop apps are not tracked or blocked.

FeatureSupportedHowLimits and bypasses
Everything outside the browserNot built—Your operating system’s own screen-time tools can help in the meantime.

What happens when enforcement fails

  • If Android stops the accessibility service, or a permission is withdrawn, the affected restrictions change to Enforcement interrupted or Permission missing. Lentivault shows a notification when it can, and records the time in the commitment’s audit trail.
  • A commitment’s timer keeps running while enforcement is interrupted. Restoring the permission does not extend or restart it.
  • If a timer cannot be enforced at all, it is marked Enforcement failed instead of pretending to have worked.
